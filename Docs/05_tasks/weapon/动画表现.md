# 武器动画表现开发方案

## 1. 目标与边界

补齐开火、换弹、装备和卸装的动画表现，同时保持现有职责：

- `WeaponBase`：管理开火、换弹状态、计时和弹药结算。
- `WeaponPresentationComponent`：把 Gameplay 事件转换为动画、音效等表现指令。
- `BP_PlayerCharacter`：复用 GASPALS Overlay 和 AnimInstance 播放具体 Montage。
- Anim Notify：处理弹匣显隐、局部音效、抛壳等表现，不直接修改弹药。

统一结构：

```text
WeaponBase / WeaponComponent 产生 Gameplay 事实
-> WeaponPresentationComponent 生成标准 FWeaponAnimationCue
-> BP_PlayerCharacter / AnimInstance 在正确 Mesh 和 Slot 上执行
```

不新增动画组件，也不让 `WeaponBase`、输入蓝图或 Anim Notify 直接播放/结算 Gameplay。GASPALS Overlay 负责持续持枪姿势、武器 Mesh 和手部 IK；Montage 只负责开火、换弹和装备等临时动作。

数据驱动目标：动作语义由 C++ 固定，动画资源由数据配置。更换同一武器族的 Fire/Reload/Equip 动画时，只修改 Animation Profile 或 Chooser Table，不修改 C++ 和角色蓝图。

弹药结算不能只依赖 Anim Notify。后续联机或无动画角色仍需要由 Gameplay 计时可靠完成换弹。

## 2. 当前状态

- 步骤 1 已完成：`WeaponBase` 已提供 `OnReloadStarted`、`OnReloadFinished`、`OnReloadCanceled` 三类互斥事件。
- `WeaponBase` 的旧 `ReloadSound` 播放逻辑已移除；步骤 2 接入表现组件前，换弹暂时没有这条基础音效。
- `WeaponDataAsset` 已有 `FireMontage`、`ReloadMontage`、`EquipMontage`，目前尚未形成统一调用链。
- 直接把 Montage 放在 `WeaponDataAsset` 只能满足单角色、单骨架原型，暂时不能优雅支持不同角色动画族和第一/第三人称。
- `WeaponPresentationComponent` 已集中处理射击 VFX、音效、后坐力、Tracer 和命中反馈，但还没有动画 Cue 通道。
- 换枪、卸装、死亡或关闭战斗时，需要可靠停止旧 Montage 和残留表现。

## 3. 推荐事件流

```text
成功开火
WeaponBase.OnWeaponShot
-> WeaponPresentationComponent
-> FWeaponAnimationCue(Fire)
-> BP_PlayerCharacter 播放 FireMontage

开始换弹
WeaponBase.OnReloadStarted
-> WeaponPresentationComponent
-> FWeaponAnimationCue(ReloadStarted) + ReloadSound
-> BP_PlayerCharacter 播放 ReloadMontage

换弹完成/取消
WeaponBase.OnReloadFinished / OnReloadCanceled
-> WeaponPresentationComponent
-> Reload Stop Cue
-> BP_PlayerCharacter 收口 Montage 和临时弹匣表现

装备/卸装
WeaponComponent.OnCurrentWeaponChanged
-> WeaponPresentationComponent
-> 新武器先进入 VisualPending
-> BP_PlayerCharacter 更新 GASPALS Overlay 并调用 SetVisualSource
-> PresentationState == Ready 后广播 Equipped Cue
```

已新增统一动画语义和不可变指令：

```cpp
enum class EWeaponAnimationCueType : uint8
{
    Fire,
    ReloadStarted,
    ReloadFinished,
    ReloadCanceled,
    Equipped,
    Unequipped
};

USTRUCT(BlueprintType)
struct FWeaponAnimationCue
{
    GENERATED_BODY()

    UPROPERTY(BlueprintReadOnly)
    EWeaponAnimationCueType CueType = EWeaponAnimationCueType::Fire;

    UPROPERTY(BlueprintReadOnly)
    TObjectPtr<AWeaponBase> SourceWeapon = nullptr;

    UPROPERTY(BlueprintReadOnly)
    TObjectPtr<UAnimMontage> Montage = nullptr;

    UPROPERTY(BlueprintReadOnly)
    float PlayRate = 1.0f;

    UPROPERTY(BlueprintReadOnly)
    float BlendOutTime = 0.15f;

    UPROPERTY(BlueprintReadOnly)
    int32 ActionId = 0;
};
```

通过一个 `OnWeaponAnimationRequested` Delegate 发送所有动画指令。`ActionId` 用于识别旧武器或旧换弹动作的延迟回调，避免它们停止、清理新武器的 Montage。

已完成：

- 切换武器时完整解绑旧武器的射击和换弹事件，并使旧 `ActionId` 失效。
- 成功射击才广播 `Fire`，空仓和射速限制不播放动画。
- 换弹开始时播放基础换弹声音并广播动画指令。
- 完成、取消、卸装和 EndPlay 时广播对应收口指令并执行统一清理。
- 新武器先进入 `VisualPending`；只有 `SetVisualSource()` 使当前武器进入 `Ready` 后才广播一次 `Equipped`，不依赖蓝图和组件 Delegate 的执行顺序。
- Montage 为空时安全跳过，不影响 Gameplay 状态。
- Montage 结束回调只负责清理表现，不能补弹或改变 Gameplay 状态。

当前运行时优先从已解析的 `UWeaponAnimationProfile` 构造 Cue；Profile 缺失或条目资源为空时，继续从 `WeaponDataAsset.FireMontage / ReloadMontage / EquipMontage` 构造 fallback Cue。换弹播放率统一在 C++ 中按 TimingPolicy 解析。

### 步骤 3：接入 GASPALS（3A 已完成，3B 最小换弹链已完成）

#### 3A：C++ 数据与解析层（已完成）

修改：

```text

Source/GASPALS/Weapons/WeaponAnimationTypes.h
```

开发流程：

1. 增加 GameplayTags 和 UE Chooser 运行时依赖；定义 `CharacterAnimationFamily + WeaponAnimationFamily + ViewMode` 查询 Context，当前视角默认 `ThirdPerson`。
2. `WeaponDataAsset` 增加 `WeaponAnimationFamily`，`ANXCharacterBase` 增加 `CharacterAnimationFamily`，并提供只读查询接口。
3. `WeaponPresentationComponent` 只在装备、角色动画族或视角变化时查询 `CHT_NXWeaponActionAnimations`，缓存 `CurrentAnimationProfile` 并预加载 Montage；禁止每发开火查询 Chooser 或 `LoadSynchronous()`。
4. 从 Profile Entry 解析 Montage、Section、TimingPolicy、BlendOutTime 和 RetriggerPolicy，生成完整 Cue。Reload 的 `FitGameplayDuration` 在 C++ 中按 `MontageLength / ReloadTime` 计算，蓝图不重复计算。
5. 保留降级顺序：精确 Profile -> 默认 Profile -> `WeaponDataAsset` 旧 Montage -> 空 Montage Cue。资源缺失不能阻塞 Gameplay。
6. 提供当前 Profile、角色动画族和武器动画族的调试查询接口；切枪或 Context 变化时使旧异步结果和旧 `ActionId` 失效。

实现结果：

- Context 只包含角色动画族、武器动画族和视角，不向 Chooser 暴露运行时角色或武器对象。
- Profile 仅在切枪、WeaponData、角色动画族或视角变化时解析；射击热路径只读取缓存。
- Montage 使用异步预加载；请求代次防止旧结果覆盖新武器，加载期间发生其他动作时会跳过迟到的 Equip Cue。
- Reload Finished/Canceled 复用 Started 时保存的 Cue 和 `ActionId`，不会因异步 Profile 变化指向另一套 Montage。
- Chooser 有匹配结果时使用该 Profile，无匹配时使用 Default Profile；当前 Profile 的动作资源缺失时继续降级到 WeaponData 旧 Montage，再降级为空 Montage Cue。资源缺失不阻塞 Gameplay。

验证：完整 UHT/C++ 冷编译通过；`DA_Rifle.WeaponAnimationFamily` 和组件调试字段已进入反射；`BP_PlayerCharacter`、`BP_Rifle` 编译通过。默认关卡 PIE 中未配置 Chooser/Profile 时，`bAnimationProfileReady=true`、`CurrentAnimationProfile=None`，且无 `Blueprint Runtime Error`、`Accessed None`、ensure 或 Fatal。Gameplay Tags、Profile、Chooser 资产配置与持枪动画联合测试属于 3B/3C。

开发流程：

1. **准备动画资源与 Slot**：使用 `RTG_UE5_Manny_to_UEFN_Mannequin` 将动作重定向到当前 UEFN 骨架并创建 Montage。通过 Skeleton Slot Manager 新建 `DefaultGroup.NXWeaponAction`，所有武器 Montage 使用该 Slot；当前先接入 Reload，Fire、Equip 和 Unequip 后续补齐。
2. **接入角色 AnimBP**：当前姿势链为 `DefaultSlot -> NX_PreWeaponAction Cache -> NXWeaponAction Slot -> Layered Blend per Bone -> Offset Root Bone`。`NXWeaponAction` 从 `spine_01` 开始覆盖上半身，Hand IK 条件同时读取该 Slot 的激活状态，因此换弹可以与移动叠加并在动作期间正确释放左手 IK。
3. **创建 Profile 与 Chooser**：当前 `PDA_Anim_UEFN_Rifle` 已接入 Reload=`FitGameplayDuration + IgnoreIfPlaying`，先通过 `DefaultAnimationProfile` 完成最小闭环。后续创建 `CHT_NXWeaponActionAnimations`，输入使用 `FWeaponAnimationSelectionContext`，输出使用 `UWeaponAnimationProfile`，按角色动画族、武器动画族和 ViewMode 返回 Profile，不修改 GASPALS 插件的 `CHT_OverlayPoses`。
4. **填写资产引用**：设置 `DA_Rifle.WeaponAnimationFamily`、`BP_PlayerCharacter.CharacterAnimationFamily`，并把 Chooser 填入 `WeaponPresentationComp.AnimationProfileChooser`。首次联调先把 Profile 直接填入 `DefaultAnimationProfile` 验证播放链，成功后再清空默认值验证 Chooser 规则。
5. **使用原生角色执行器**：`ANXCharacterBase` 在组件初始化后绑定 `OnWeaponAnimationRequested`，验证 `SourceWeapon + ActionId` 后统一执行 Cue。`Fire/ReloadStarted/Equipped` 负责播放，`ReloadFinished` 自然收尾，`ReloadCanceled` 停止对应 Montage，`Unequipped` 只停止本执行器启动的武器 Montage。播放时消费 Montage、StartSection、PlayRate、BlendOutTime 和 RetriggerPolicy，并使用 `bStopAllMontages=false` 保护 GASPALS 的其他 Montage Group；`BP_PlayerCharacter` 中的临时 Delegate/Play Montage 链已移除。
6. **保持装备边界**：装备顺序保持为 `逻辑装备 -> 更新 Overlay/手部 IK -> SetVisualSource() -> Ready -> Equipped Cue`；卸装先取消动作，再 `ClearVisualSource()` 和清除 Held Object。当前流程会立即切换武器，因此 Unequipped 第一阶段仅作为停止和清理信号；完整收枪动画需要后续增加 Unequip Started/Committed 状态流程。
7. **按最小闭环联调**：先回归 Reload 正常完成、连续按 R 和切枪取消，再接 Fire、Equip，最后接 Gameplay Tags 与 Chooser。蓝图只维护 AnimGraph、Slot、骨骼遮罩和资源配置，不读取弹药、不重新判断动作是否合法，也不计算 ReloadTime。

当前结果：UE 5.8 完整 UHT、C++ 编译和 DLL 链接通过；Reload 重定向资源、Montage、Profile、AnimBP Slot 以及原生执行器已经接入。删除临时蓝图播放链后的 Reload/Cancel/快速切枪仍需完成一次 PIE 回归。

## 5. 数据驱动动画配置

### 5.1 配置分层

```text
WeaponDataAsset
  WeaponAnimationFamily = Animation.Weapon.Rifle.Standard

Character / Animation Config
  CharacterAnimationFamily = Animation.Character.GASPALS.Manny

CHT_NXWeaponActionAnimations
  CharacterFamily + WeaponFamily + ViewMode
  -> UWeaponAnimationProfile

UWeaponAnimationProfile
  -> Fire / Reload / Equip / Unequip Animation Entry
```

Chooser Table 只负责“选择哪套动画”，Profile 负责“这一套包含哪些资源和播放策略”。这样表格不会重复填写大量 Montage 参数，也不会把角色骨架绑定到 `DA_Rifle`。

示例行：

```text
GASPALS.Manny | Rifle.Standard | ThirdPerson | PDA_Anim_Manny_Rifle
GASPALS.Manny | Pistol.Standard | ThirdPerson | PDA_Anim_Manny_Pistol
NexAur.HeroA | Rifle.Standard | ThirdPerson | PDA_Anim_HeroA_Rifle
```

### 5.2 Animation Profile

`UWeaponAnimationProfile : UPrimaryDataAsset` 保存动作条目。条目至少包含：

```text
CharacterMontage       角色 Montage，使用 SoftObjectPtr
StartSection           可选 Montage Section
BasePlayRate           默认播放速率
BlendOutTime           收尾混合时间
TimingPolicy           Natural / FitGameplayDuration / FixedPlayRate
RetriggerPolicy        Restart / IgnoreIfPlaying / Continue / Section
```

`FitGameplayDuration` 用于换弹：

```text
PlayRate = MontageLength / WeaponData.ReloadTime
```

Profile 资源为空时必须安全跳过；不可因为表现资源缺失阻塞弹药、射线或伤害逻辑。

### 5.3 运行时解析与 fallback

```text
装备武器
-> 读取 CharacterAnimationFamily 和 WeaponAnimationFamily
-> 查询 CHT_NXWeaponActionAnimations 一次
-> 缓存 CurrentAnimationProfile
-> 预加载 Profile 中的 Montage

成功开火/换弹
-> 从缓存 Profile 获取 Entry
-> 构造 FWeaponAnimationCue
-> BP_PlayerCharacter 执行
```

解析优先级：

1. 角色动画族 + 武器动画族 + 当前视角的精确匹配。
2. 角色动画族 + 通用武器动画族。
3. 项目默认 Profile。
4. 无 Profile 时回退到 `WeaponDataAsset` 旧 Montage 字段，仍没有资源则跳过。

禁止在每发开火时查询 Chooser 或 `LoadSynchronous()`。更换武器、角色模型或视角时才重新解析 Profile。

单角色迁移阶段保留 `WeaponDataAsset` 中现有的 `FireMontage`、`ReloadMontage` 和 `EquipMontage` 作为兼容 fallback。确认 Profile 链路稳定后，再删除旧字段。

第一阶段 `Unequipped` 只负责停止 Montage 和清理残留表现，不等待收枪动画。以后若需要“先播放收枪，再真正切换武器”，应建立可取消的 Equipping/Unequipping Gameplay 流程，不能靠延迟蓝图节点阻塞现有 `WeaponComponent`。

## 6. GAS 兼容边界

当前动画 Cue 保持 GAS 无关，不依赖 `AbilitySystemComponent`。后续接入 GAS 时只替换事件来源：

```text
当前：输入 -> CombatComponent -> WeaponBase -> FWeaponAnimationCue
未来：GameplayAbility -> WeaponBase/GameplayEvent -> FWeaponAnimationCue 或 GameplayCue
```

- `GA_WeaponFire`、`GA_WeaponReload` 可以先包装现有武器接口，再逐步接管激活、取消和状态 Tag。
- `State.Weapon.Reloading`、`State.Weapon.Aiming` 后续可替代对应运行时状态查询，但表现层只消费结果。
- `WeaponAnimationFamily` 和 `CharacterAnimationFamily` 可以使用 Gameplay Tags，但 Profile 和 Chooser 不应依赖 `AbilitySystemComponent`。
- 伤害和生命值已迁移到 `GameplayEffect + AttributeSet`，不会改变动画 Cue、散布、后坐力和命中特效的职责边界。
- 弹匣弹药可以继续保存在可复制的 Weapon Actor，不要求全部迁入 AttributeSet。
- 联机阶段需要复制的动画/VFX 可改由 GameplayCue 发送；`BP_PlayerCharacter` 的 Montage 执行逻辑仍可复用。

因此现在最重要的约束是：动画和 Notify 永远不能决定开火、补弹或伤害是否成功。

## 7. 验收清单

- [ ] 半自动和全自动的每次成功射击只播放一次 Fire Montage。
- [ ] 空仓、射速限制和换弹期间不会播放 Fire Montage。
- [ ] Reload Montage、HUD 换弹状态和实际弹药结算时间一致。
- [ ] 换枪、卸装、死亡和关闭战斗可以中断换弹且不补弹。
- [ ] 快速装备/卸装不会收到旧武器动画回调。
- [ ] Montage 或声音资源为空时，开火和换弹逻辑仍正常。
- [ ] 弹匣临时 Mesh 在完成和所有取消路径中都能正确清理。
- [ ] 旧武器或旧 `ActionId` 的延迟 Montage 回调不会影响当前武器。
- [ ] GASPALS Overlay 只在装备状态变化时更新，开火和换弹不会重复切换 Overlay。
- [ ] 修改 Animation Profile 后，不修改 C++ 和角色蓝图即可替换 Fire/Reload/Equip 动画。
- [ ] 不同 CharacterAnimationFamily 能从 Chooser Table 选择不同 Profile。
- [x] Profile 缺失时按 fallback 顺序安全降级，且不影响 Gameplay。
- [x] 开火热路径不查询 Chooser，C++ 动画解析路径不调用同步加载。
