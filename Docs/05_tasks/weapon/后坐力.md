# 后坐力、动态散布与准心开发方案

## 1. 系统目标与边界

系统分为四条数据链：

- Gameplay 散布：`WeaponBase` 计算本次真实射线方向。
- AccuracyState：`WeaponBase` 发布只读精度快照，HUD 只消费。
- 视觉后坐力：方向性镜头偏移和可选 Camera Shake，只负责表现。
- Aim Recoil：由玩家侧组件维护的逻辑瞄准偏移，会影响后续射线；不直接修改 Control Rotation。

基本规则：

- DataAsset 只保存静态配置，不保存运行时 Bloom。
- 蓝图不重新计算散布，不修改 `CurrentSpreadBloom`。
- 准心只显示 AccuracyState，不能反向决定射线方向。
- 空仓、射速限制和换弹失败不增加散布，也不产生后坐力。

当前已有基础：

- `WeaponBase::ApplySpreadToDirection()` 已使用 `SpreadAngle + CurrentSpreadBloom + VRandCone`。
- `FWeaponShotEvent.AimDirection` 已保存每次射击的实际方向。
- `WeaponPresentationComponent` 已只响应成功射击事件。
- `CombatHUDWidgetBase` 已负责绑定当前武器并向 UMG 推送状态。
- `WBP_Crosshair` 已能显示固定准心。

## 2. 总体数据设计

### 2.1 WeaponDataAsset 静态配置

阶段 1 保留现有 `SpreadAngle`，增加连续射击参数：

```text
SpreadPerShot        每次成功射击增加的 Bloom，单位 deg
MaxSpreadBloom       连续射击 Bloom 上限，单位 deg
SpreadRecoveryDelay  最后一发后等待多久开始恢复，单位 s
SpreadRecoveryRate   每秒恢复多少 Bloom，单位 deg/s
```

阶段 2 增加视觉后坐力：

```text
RecoilPitchMin/Max   单发视觉上跳范围
RecoilYawMin/Max     单发视觉水平偏移范围
RecoilKickSpeed      视觉偏移施加速度，单位 deg/s
RecoilReturnSpeed    视觉偏移回正速度，单位 deg/s
CameraShakeClass     可选 UCameraShakeBase 资源
CameraShakeScale     细碎震动强度，不代替方向性 Pitch/Yaw
RecoilMode           VisualOnly 或 GameplayAim
```

阶段 4 再增加：

```text
AimBaseSpread        ADS 基础散布
MovementSpreadAngle  移动附加散布
AirborneSpreadAngle  滞空附加散布
```

新增散布参数全部为 `0` 时，必须保持当前固定 `SpreadAngle` 行为。

### 2.2 WeaponBase 运行时状态

只保存连续射击产生的额外 Bloom：

```cpp
float CurrentSpreadBloom = 0.0f;
double LastSpreadUpdateTime = 0.0;
FTimerHandle SpreadRecoveryTimerHandle;
```

最后成功射击时间复用现有 `LastFireTime`。

```text
阶段 1：FinalSpread = SpreadAngle + CurrentSpreadBloom

阶段 4：FinalSpread = BaseSpread
                      + CurrentSpreadBloom
                      + MovementSpread
                      + AirborneSpread
```

开发流程：

1. 创建 `WeaponAccuracyTypes.h`，加入 `FWeaponAccuracyState` 和动态多播委托 `FOnWeaponAccuracyChangedSignature`。委托参数包含 `AWeaponBase*` 和状态快照。
2. 在 `WeaponDataAsset` 增加 `SpreadPerShot`、`MaxSpreadBloom`、`SpreadRecoveryDelay`、`SpreadRecoveryRate`。字段使用非负 Clamp 和正确单位，不加入 `IsValidWeaponData()`，避免表现配置阻止开火。
3. 在 `WeaponBase` 增加 `CurrentSpreadBloom`、恢复 Timer、公开 Getter 和 `OnAccuracyStateChanged`。缓存上一份快照，数值没有变化时不重复广播。
4. 调整 `FireOnceFromTrace()`：开火前先按时间恢复 Bloom，使用当前最终角度计算本发方向；本发正式成立并扣弹后，再增加 Bloom。
5. 实现恢复 Timer。Timer 约 `30Hz` 用于持续更新状态；每次开火前仍主动按世界时间刷新，避免帧率影响 Gameplay。
6. `InitializeWeapon()` 和 `SetWeaponData()` 重置 Bloom 并强制广播；`EndPlay`、销毁和卸装时清理 Timer。换弹期间继续恢复 Bloom。

射击调用顺序：

```text
CanFire 通过
-> UpdateSpreadRecovery()
-> FinalSpread = SpreadAngle + CurrentSpreadBloom
-> ApplySpreadToDirection()
-> 验证方向有效
-> 记录 LastFireTime 并扣弹
-> AddSpreadForSuccessfulShot()
-> 执行射线、伤害和 ShotEvent
```

必须先计算方向，再增加 Bloom，因此第一枪只使用基础散布。

恢复公式：

```text
RecoveryStart = LastFireTime + SpreadRecoveryDelay
EffectiveStart = Max(LastSpreadUpdateTime, RecoveryStart)
Elapsed = Max(0, Now - EffectiveStart)
Recovered = Elapsed * SpreadRecoveryRate
CurrentSpreadBloom = Max(0, CurrentSpreadBloom - Recovered)
```

推荐内部函数：

```cpp
void UpdateSpreadRecovery();
void AddSpreadForSuccessfulShot();
void StartSpreadRecoveryTimer();
void StopSpreadRecoveryTimer();
float GetCurrentSpreadAngle() const;
FWeaponAccuracyState BuildAccuracyState() const;
void BroadcastAccuracyStateChanged(bool bForce = false);
```

`ApplySpreadToDirection()` 只读取最终角度并生成方向，不修改 Bloom。

## 5. 阶段 2：RecoilCue 与视觉后坐力

完成状态：5.1、5.2 C++ 已完成（完整构建通过）；多相机模式 PIE 验收与 5.3 蓝图接入待进行

当前项目已启用 UE5.8 Gameplay Camera，`BP_PlayerCharacter` 实际使用 `GameplayCameraComponent`，普通的 `Camera(NotUsedByDefault)` 不参与默认视图。阶段 2 不直接查找或修改普通 `UCameraComponent`。

### 5.1 前置：隔离逻辑瞄准与视觉相机

改造前 `WeaponBase::GetTraceView()` 使用 `Controller->GetPlayerViewPoint()` 同时取得起点和方向。该旋转来自最终 PlayerCameraManager POV，可能已经包含 Camera Shake 或 Camera Modifier，直接接后坐力会让下一发射线读到视觉偏移。

当前实现优先读取 Gameplay Cameras 的 Pre-Visual 结果：

```text
IGameplayCameraSystemHost.FindActiveHost
-> CameraSystemEvaluator.GetPreVisualLayerEvaluatedResult
-> CameraPose.Location + CameraPose.Rotation

Gameplay Camera 尚未就绪时：
射线观察起点 = Controller.GetPlayerViewPoint().Location
逻辑瞄准方向 = Controller.GetControlRotation().Vector

视觉相机结果 = Gameplay Camera + Camera Modifier + Camera Shake
```

`WeaponBase` 已将入口收口为 `GetLogicalAimView()`，并在 `GASPALS.Build.cs` 增加 `GameplayCameras` 私有依赖。Pre-Visual 结果保留各 Camera Rig 的构图，同时排除 Visual Layer 中的震动和偏移；Controller、Owner 与武器朝向组成逐级回退链。

只允许本阶段后续的 Modifier 和 Shake 修改旋转，不修改相机位置或 FOV。仍需在 PIE 验证 GASPALS 的 Aim、Freecam、Strafe 和第一人称相机样式。

### 5.2 C++ 端工作

修改和新增：

```text
Source/GASPALS/Weapons/WeaponBase.cpp
Source/GASPALS/Weapons/WeaponDataAsset.h
Source/GASPALS/Weapons/WeaponRecoilTypes.h（新增）

Source/GASPALS/Player/PlayerRecoilComponent.h/.cpp（新增）
Source/GASPALS/Player/WeaponRecoilCameraModifier.h/.cpp（新增）
```

开发流程：

1. 先按 5.1 调整逻辑瞄准方向，禁止最终视觉旋转反向进入本发或下一发射线。
2. DataAsset 增加 Pitch/Yaw 范围、KickSpeed、ReturnSpeed、可选 `CameraShakeClass` 和 `CameraShakeScale`；默认值为 `0/null` 时保持现状。
3. `FWeaponRecoilCue` 保存本发完整快照：Pitch、Yaw、KickSpeed、ReturnSpeed、Shake 资源、Scale 和 `ShotSequence`。消费者不再回查当前武器，避免耦合和换枪时序问题。
4. `WeaponPresentationComponent` 增加 `OnRecoilRequested`，在 `HandleWeaponShot()` 校验成功后生成并广播一次 Cue；组件不访问 Controller 或 Camera。
5. `UPlayerRecoilComponent` 仅对本地控制玩家生效，自动绑定/解绑 `WeaponPresentationComponent` 和 `WeaponComponent`，维护 GameplayAim/VisualOnly 两条运行时状态，并按需创建 Camera Modifier。
6. `UPlayerRecoilComponent` 自己按 `DeltaTime` 推进和回正共享状态，避免关闭相机表现时逻辑压枪停止；`UWeaponRecoilCameraModifier` 只读取共享视觉偏移并写入最终 POV。
7. `GameplayAim` 通过 `WeaponBase::GetLogicalAimView()` 叠加到 Pre-Visual 基础方向，不修改 `ControlRotation`；第一版不使用 `AddControllerPitchInput`。
8. `EndPlay`、换枪和卸装时解绑委托并清空两条后坐力通道，移除本组件创建的 Modifier 和 Camera Shake。

短期使用 PlayerCameraManager 的 `UCameraModifier`，它能叠加在 Gameplay Camera 最终结果上。后续若迁移到 Gameplay Cameras 的 Visual Camera Modifier Rig，只替换 `PlayerRecoilComponent` 内部执行器，不改变 Cue 和武器表现事件契约。

当前 C++ 已实现完整链路：DataAsset 默认零配置、稳定随机 RecoilCue、成功射击广播、本地玩家自动绑定、GameplayAim/VisualOnly 双通道状态、方向偏移累积/限幅/回正，以及本组件创建的 Camera Modifier 与 Camera Shake 生命周期清理。

5.2 局部重构后的核心规则：

```text
PlayerRecoilComponent
    CurrentGameplayAimOffset -> WeaponBase.GetLogicalAimView()
    CurrentVisualOffset      -> WeaponRecoilCameraModifier
    两者合成                 -> 最终视觉相机
```

`WeaponRecoilCameraModifier` 不再自己保存 Pending/Current 后坐力，也不再推进状态；它只是读取 `PlayerRecoilComponent` 的合成视觉偏移。状态由组件自身按 `DeltaTime` 推进，因此关闭 Camera Modifier 不会停止 GameplayAim 的回正。

`GameplayAim` 会让下一发逻辑射线和镜头一起上抬，玩家可以向下输入进行压枪；`VisualOnly` 只影响最终画面，适合不希望改变命中方向的武器。换枪、卸装和 CameraManager 重建时会清空两条通道，避免旧武器后坐力残留。

武器及人物 Additive Montage 不属于本阶段，继续在 `动画表现.md` 中开发。
